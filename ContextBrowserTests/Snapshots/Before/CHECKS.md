# Snapshots / Before — чек-лист симптомов

Для каждого снапшота (`R1_*.puml` … `R8_*.puml`) пробеги **10 проверок**.
Отметь результат `[x]` (симптом есть) или `[ ]` (симптома нет).

Цель — получить матрицу «симптом × сценарий», которую будем
использовать как baseline для проверки улучшений.

## Как проверять (для каждого снапшота)

Открыть `.puml` в текстовом редакторе. Пройтись по 10 пунктам.
Ниже — на что смотреть.

### S1 — Точка входа без источника

**Что искать:**

```
  --> X : Y
```

Строка начинается с `-->` (без участника слева) — признак S1.

**Что должно быть:** `Actor "..." as ...` или `participant "..."`,
от которого идёт первая стрелка.

### S2 — `Actor` для не-людей

**Что искать:**

```
  Actor "ToHashSet" as ToHashSet
  Actor "Select" as Select
```

`Actor` применён к имени класса/метода. В PlantUML `Actor` — это
человечек (stick figure). Для `System.Linq.Enumerable` — не подходит.

**Что должно быть:** `participant "..." as ...` для всех
не-человеческих сущностей.

### S3 — Участник = имя метода

**Что искать:**

Участник объявлен с именем, совпадающим с известным extension-методом:
`ToHashSet`, `Select`, `ToList`, `Where`, `First`, `Any`, `All`, ...

**Что должно быть:** один участник `System.Linq.Enumerable` для всех
LINQ-методов. Или вообще без участника (inline).

### S4 — Дисбаланс `activate` / `deactivate`

**Что искать:**

```
grep -c "^activate"     <file>
grep -c "^deactivate"   <file>
```

Числа должны совпадать. Если `activate` больше — где-то нет парного
`deactivate`. Если `deactivate` больше — есть «висячий» `deactivate`.

### S5 — Возвраты без типа

**Что искать:**

```
  X --> Y : done
```

Все возвраты помечены `done`. Это не тип.

**Что должно быть:**

```
  X --> Y : HashSet<string>
  X --> Y : IEnumerable<T>
  X --> Y : List<ContextInfoSerializableModel>
```

### S6 — Self-call caller

**Что искать:**

```
  X -> X : methodName
```

Стрелка от участника к самому себе с именем метода. В нормальном
sequence это возможно (рекурсия), но **не на каждом** переходе.

**Что должно быть:** self-call только при реальной рекурсии.
Если `X -> X: ToHashSet` появляется для каждой LINQ-цепочки — это S6.

### S7 — Дублирующие `activate` подряд

**Что искать:**

```
  activate X
  activate X      ← дубль
```

Два `activate X` подряд без промежуточного `deactivate X`.

**Что должно быть:** один `activate X` на один вызов.

### S8 — Порядок вызовов не соответствует цепочке

**Что искать:**

Для `Adapt(List).Select(Adapt).ToList()` — ожидаемая цепочка:
`Select → (loop по элементам) → Adapt → ToHashSet × 4 → List`.

Если в снапшоте порядок, например, `ToList → Select → ToList → Select` —
это S8.

### S9 — Нет `loop` для LINQ-материализации

**Что искать:**

```
  loop
    ...
  end
```

Отсутствие `loop` там, где метод (`ToList`, `ToArray`, `ToHashSet`)
материализует `IEnumerable`.

**Что должно быть:**

```
  loop для каждого элемента
    ...
  end
```

### S10 — Лишний `deactivate` в начале следующего блока

**Что искать:**

```
  ... (конец блока 1)

  deactivate Y    ← лишний, не связан с текущим блоком
  activate Z      ← начало блока 2
```

Лишний `deactivate` в самом начале блока — «хвост» предыдущего.

**Что должно быть:** каждый блок — сбалансирован. Блок начинается
с `activate`, заканчивается `deactivate`.

## Формат записи результата

Обновляй матрицу выше. Если симптом есть — `x`. Если нет — пустая клетка.

После заполнения матрицы — **сводка по симптомам**:

```
S1: 5/8 сценариев
S2: 8/8 сценариев
S3: 3/8 сценариев
…
```

Эта сводка — baseline для сравнения после фиксов. Она же — обоснование
для приоритетов: чем больше сценариев задето, тем выше Priority
соответствующей подзадачи в Jira.
